도구 팩 작성하기

도구 팩은 Python 함수를 에이전트가 호출할 수 있는 MCP 도구로 바꿔 주는 작은 Python 파일입니다. 이 가이드는 브라우저를 벗어나지 않고 빌더에서 팩을 작성하고, 테스트하고, 게시하는 방법을 설명합니다.

팩이란

Daedalus는 도구로 MCP 서버를 만듭니다. REST 도구는 API 작업 하나를 매핑하며 코드가 필요 없습니다. 팩 도구는 그 외의 모든 경우를 위한 Python 함수입니다. 여러 번의 호출을 조합하거나, 결과를 계산하거나, 응답을 가공하거나, 단순한 REST 엔드포인트가 아닌 시스템과 통신할 때 사용합니다.

함수는 하나의 Python 모듈인 팩 안에 있습니다. 팩의 출처는 두 가지입니다.

출처위치변경 권한
기본 제공런타임 이미지 내부 (예: demo 팩)빌더에서는 변경할 수 없으며 이미지와 함께 바뀝니다
프로젝트프로젝트 스토리지의 파일, 빌더에서 작성관리자가 팩 편집기에서 변경

두 종류 모두 구성 요소 패널의 도구 팩 섹션에 표시됩니다. 누구나 코드 보기로 코드를 읽을 수 있습니다.

빌더에서 팩 만들기

  1. 관리자로 로그인합니다. 작성자와 게시자는 팩을 사용할 수는 있지만 작성할 수는 없습니다.
  2. 왼쪽 패널의 도구 팩 옆에 있는 +를 클릭합니다. 동작하는 템플릿이 채워진 편집기가 열립니다.
  3. 팩 이름을 정합니다. 소문자, 숫자, 밑줄만 사용하고 문자로 시작해야 합니다 (예: hdfs_files). 이름은 나중에 변경할 수 없습니다.
  4. 함수를 작성하고 (도구의 구조 참고) 팩 저장을 클릭합니다. Daedalus가 격리된 프로세스에서 파일을 불러와 문제가 있으면 줄 번호와 함께 알려 줍니다. 파일이 유효할 때까지 아무것도 저장되지 않습니다.
  5. 이제 패널에 팩과 도구가 표시됩니다. 도구를 클릭하거나 캔버스로 끌어다 놓으면 도구 레코드가 만들어집니다. 모두 추가는 함수마다 레코드를 하나씩 만듭니다.
  6. 도구를 선택하고 도구 테스트를 클릭한 뒤, 샘플 인수를 조정하고 실행합니다. 그 다음 다른 도구와 마찬가지로 검토 및 게시합니다.
어느 단계에서도 재시작은 필요 없습니다. 팩을 저장하면 팔레트가 즉시 갱신되고, 릴리스를 게시하면 서버에서 코드가 실행됩니다.

도구의 구조

"""팩을 한 줄로 설명합니다. 팔레트에 표시됩니다."""
from factory.packs import ToolContext, pack_tool


@pack_tool(effect="read", requires_connection=False)
def hello(ctx: ToolContext, name: str, excited: bool = False) -> dict:
    """이름으로 인사합니다. 사용자가 인사를 요청할 때 사용하세요."""
    greeting = f"Hello, {name}" + ("!" if excited else ".")
    return {"greeting": greeting, "user": ctx.caller.username}
구성 요소역할규칙
모듈 독스트링팔레트의 팩 설명선택 사항이지만 권장
@pack_tool(...)함수를 도구로 표시필수. effect는 "read" 또는 "write", 도구가 API 연결을 호출하면 requires_connection을 True로 설정
함수 이름기본 도구 이름유효한 Python 식별자. 도구 레코드의 이름은 나중에 바꿀 수 있음
첫 번째 매개변수 ctxToolContext이름이 반드시 ctx여야 하며 도구 입력에 포함되지 않음
나머지 매개변수도구의 입력 스키마str, int, float, bool 타입 어노테이션 필요. 기본값이 있으면 선택 입력이 됨
함수 독스트링에이전트가 읽는 도구 설명필수. 도구가 무엇을 하고 언제 사용해야 하는지 설명
반환값구조화된 결과JSON으로 직렬화할 수 있는 값. dict가 가장 좋음
에이전트는 입력을 body 아래에 중첩해서 보냅니다. hello를 호출하면 {"body": {"name": "Ada"}} 형태가 됩니다. 플레이그라운드가 이 형태를 미리 채워 줍니다.

ToolContext

모든 호출은 ctx를 받습니다. 도구는 헤더, 토큰, 환경 변수를 직접 읽지 않습니다. 컨텍스트가 도구에 허용된 정보만 전달합니다.

멤버의미
ctx.caller.username이 요청에서 서버가 대신 동작하는 사용자입니다. 로컬 개발 환경에서는 development이고, 운영 환경에서는 호출자 토큰에서 검증된 신원입니다.
ctx.caller.token연결이 토큰을 전달하도록 설정된 경우 호출자의 자격 증명이며, 그렇지 않으면 None입니다. 로그에 남기지 마세요.
ctx.connection도구의 연결 레코드(name, base_url, auth_mode)이며, 연결이 없는 도구에서는 None입니다.
ctx.client(timeout=10.0)연결의 승인된 기본 URL에 바인딩되고 연결의 인증이 적용된 httpx.Client입니다. 모든 API 호출에 이 클라이언트를 사용하세요. 서버의 오리진 정책을 지키는 유일한 경로입니다.
ctx.config인스펙터의 구성 필드에 입력한 JSON 객체입니다. 루트 경로나 페이지 크기 같은 도구별 설정에 사용합니다.

규칙과 제한

  • 임포트. 표준 라이브러리와 런타임 이미지에 포함된 라이브러리, 특히 httpx, pydantic, yaml, jsonschema를 사용할 수 있습니다. pip install은 없습니다. 다른 라이브러리가 필요하면 이미지에 추가해 달라고 요청하세요.
  • 시간. 도구는 8초 안에 끝나야 합니다. 그렇지 않으면 게이트웨이가 에이전트에 시간 초과를 보고합니다. 오래 걸리는 작업은 더 작은 도구나 백그라운드 시스템으로 나누세요.
  • 크기. 팩 파일은 최대 64 KiB입니다. 결과는 최대 1 MiB이며, 에이전트가 결과 전체를 읽으므로 결과는 작게 유지하세요.
  • 오류. 에이전트가 고칠 수 있는 문제(잘못된 경로, 권한 부족)에는 ValueError("메시지")를 발생시키세요. 에이전트는 {"error": "메시지"}를 받습니다. 그 외의 예외는 예외 타입과 함께 내부 오류로 보고됩니다.
  • 네트워크. API 호출은 ctx.client()를 통해 하세요. 그래야 연결의 승인된 오리진과 인증이 적용됩니다. 직접 연결을 여는 코드는 이 정책을 우회하므로 검토자는 결함으로 취급해야 합니다.
  • 부작용. 데이터를 생성, 변경, 삭제하는 모든 도구에는 effect="write"를 선언하세요. 쓰기 도구는 실제 테스트 전에 명시적인 확인이 필요합니다.
  • 결정성. 모듈 수준 코드는 서버가 시작될 때 한 번 실행됩니다. 임포트와 상수만 두고, 임포트 시점에 연결을 열거나 파일을 읽지 마세요.
  • 신뢰. 팩 코드는 서버 애플리케이션 안에서 그 권한으로 실행됩니다. 그래서 관리자만 팩을 작성할 수 있고, 모든 저장이 감사 로그에 기록됩니다.

예제

API를 호출하고 결과 가공하기

@pack_tool(effect="read", requires_connection=True)
def open_tickets(ctx: ToolContext, customer_id: str, limit: int = 10) -> dict:
    """고객의 열린 지원 티켓을 최신순으로 나열합니다."""
    with ctx.client() as client:
        response = client.get(f"/customers/{customer_id}/tickets", params={"status": "open"})
        response.raise_for_status()
        tickets = response.json()
    tickets.sort(key=lambda t: t["created_at"], reverse=True)
    return {"tickets": [{"id": t["id"], "title": t["title"]} for t in tickets[:limit]], "total": len(tickets)}

두 번의 호출 조합하기

@pack_tool(effect="read", requires_connection=True)
def order_summary(ctx: ToolContext, order_id: str) -> dict:
    """주문 정보와 배송 상태를 함께 반환합니다."""
    with ctx.client() as client:
        order = client.get(f"/orders/{order_id}")
        if order.status_code == 404:
            raise ValueError(f"주문 {order_id}이(가) 존재하지 않습니다")
        order.raise_for_status()
        shipment = client.get(f"/shipments", params={"order": order_id}).json()
    return {"order": order.json(), "shipment": shipment[0] if shipment else None}

도구별 구성과 호출자 사용하기

@pack_tool(effect="write", requires_connection=True)
def create_note(ctx: ToolContext, text: str) -> dict:
    """이 도구에 구성된 폴더에 메모를 기록합니다."""
    folder = ctx.config.get("folder", "/notes")
    with ctx.client() as client:
        response = client.post(f"{folder}", json={"text": text, "author": ctx.caller.username})
        response.raise_for_status()
    return {"created": response.json()["id"], "folder": folder}

인스펙터의 구성 (JSON) 필드에 폴더를 설정하세요: {"folder": "/notes/sales"}. 같은 함수로 구성이 다른 여러 도구를 만들 수 있습니다.

테스트, 게시, 편집

  • 테스트는 게이트웨이와 실행기의 비공개 복사본으로 도구를 실행하므로 초안이 실행 중인 서버에 영향을 주지 않습니다. 표시되는 결과는 에이전트가 받게 될 결과와 정확히 같습니다.
  • 게시는 팩 소스를 릴리스에 스냅샷으로 저장합니다. 실행 중인 서버는 그 스냅샷을 실행합니다.
  • 나중에 팩을 편집해도 게시된 서버는 바뀌지 않습니다. 그 팩을 사용하는 도구는 테스트됨 상태를 잃으므로, 새 코드를 배포하려면 다시 테스트하고 게시하세요. 릴리스는 스냅샷과 함께 복원할 수 있습니다.
  • 팩 삭제는 팩을 사용하는 도구가 남아 있는 동안 거부됩니다. 먼저 해당 도구를 제거하거나 다른 팩으로 옮기세요.

자주 발생하는 검증 오류

메시지해결 방법
invalid syntax (name.py, line N)해당 줄의 Python 문법 오류입니다.
the first parameter must be ctx데코레이트된 함수의 첫 번째 매개변수를 ctx: ToolContext로 만드세요.
parameter X must be a str, int, float or bool모든 입력에 이 네 가지 타입 중 하나를 어노테이션하세요. 리스트나 객체는 str로 JSON 텍스트를 받아 함수 안에서 파싱하세요.
add a docstring; it becomes the tool description에이전트가 도구를 언제 사용해야 하는지 설명하는 독스트링을 작성하세요.
